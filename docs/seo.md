# SEO Architecture

The portfolio uses Next.js App Router metadata APIs and file-based metadata routes.

## Site URL

Canonical URL generation is centralized in:

`lib/site-url.ts`

Resolution order:

1. `NEXT_PUBLIC_SITE_URL`
2. `VERCEL_PROJECT_PRODUCTION_URL`
3. `VERCEL_URL`
4. `http://localhost:3000` for local development

For a custom production domain, explicitly set:

```env
NEXT_PUBLIC_SITE_URL=https://your-domain.example
```

This value is used by metadataBase, structured data, sitemap URLs, and robots metadata.

## Canonicals

Every public route declares a canonical URL.

Static routes:

- `/`
- `/about`
- `/skills`
- `/projects`
- `/contact`

Every known project also declares:

`/projects/<slug>`

Project filter state remains client-side, so category selections do not create duplicate indexable query-string pages.

## Sitemap

`app/sitemap.ts` generates `/sitemap.xml`.

It includes all static public routes and all project case-study routes from `data/projects.ts`. Project entries are derived from the same data source used by the UI, preventing sitemap drift when projects are added or removed.

## Robots

`app/robots.ts` generates `/robots.txt`.

Public pages are crawlable. `/api/` is excluded because those routes are operational endpoints rather than indexable content.

## Open Graph and X cards

Root social images are generated by:

- `app/opengraph-image.tsx`
- `app/twitter-image.tsx`

Project-specific social images are generated per slug from:

- `app/projects/[slug]/opengraph-image.tsx`
- `app/projects/[slug]/twitter-image.tsx`

The shared renderer in `lib/social-image.tsx` accepts route-specific title, description, and label content.

## Structured data

The root layout exposes:

- `Person`
- `WebSite`

Each project route exposes project-specific structured data tied back to the portfolio author and website.

Public social-profile URLs are reused from the same source consumed by the Contact page and footer. Unconfigured LinkedIn/email values are not fabricated.

## Icons and manifest

`app/icon.svg` provides the application/favicon asset through Next.js file-based metadata.

`app/manifest.ts` references `/icon.svg` and defines the portfolio name, description, theme color, and standalone application metadata.

## Metadata strategy

`lib/metadata.ts` centralizes static route metadata:

- title
- description
- keywords
- canonical
- Open Graph
- X card

Dynamic project metadata is generated from the project record itself.

Unknown project slugs return noindex/nofollow metadata before the route resolves to not-found behavior.

## Final QA

Group 33 should verify the production deployment rather than only source code:

- canonical URLs resolve to the intended production domain,
- `/robots.txt` is reachable,
- `/sitemap.xml` contains every intended public route,
- Open Graph and X images render correctly,
- structured data passes a schema validator,
- page titles/descriptions are visible in rendered HTML,
- no preview/deployment domain is accidentally canonicalized after the custom production domain is configured.
